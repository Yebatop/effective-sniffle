# Устройство «Толмача» — для сессий Claude Code

Спецификация к [PLAN.md](PLAN.md). Владелец не программирует: всё, что
требует от него действий, описывается в PLAN.md простыми словами и
инструкцией с картинками; здесь — решения для того, кто пишет код.
Прошлый проект — `Yebatop/ExtTran` (публичный, читается `git clone`); ссылки
вида `exttran:src/x.ts:12` ведут туда.

Пометка **[проверить]** — не подтверждено и проверяется на указанном этапе
до того, как на это опираться.

## Стек

- Next.js (App Router), **один пакет** — без workspaces и `../dist`
  (exttran:web/vercel.json:4, коммит 9450098). Ядро перевода — `lib/core/`,
  без зависимостей от Next, чтобы его можно было вынести.
- Vercel Hobby, регион функций iad1. Neon Postgres в AWS us-east-1, строка
  через пулер (`-pooler`), `attachDatabasePool` из `@vercel/functions` либо
  HTTP-драйвер `@neondatabase/serverless` для одиночных запросов.
  Миграции — при сборке, не в рантайме (exttran создавал таблицы на каждый
  запрос: exttran:src/store-pg.ts:119-191, src/store.ts:623-630).
- `@anthropic-ai/sdk`, все вызовы модели — `messages.stream` +
  `finalMessage()`, в том числе в фоне.
- Установка у владельца — одна кнопка Vercel Deploy с интеграцией Neon:
  поля `ANTHROPIC_API_KEY` и `APP_PASSWORD`, остальное по умолчанию.
  Никаких ручных настроек в панели Vercel. `CRON_SECRET` не обязателен:
  ежедневный крон только забирает готовые пакеты и ничего не тратит.

## Вход и доступ

- Пароль → cookie на год: подписанный HMAC токен сессии (не сам пароль),
  `HttpOnly; Secure; SameSite=Lax`. Пароль сравнивается по хешу — кириллица
  допустима, в заголовки он не попадает. Не больше 5 попыток за 15 минут,
  счётчик в БД.
- Без пароля доступны: `/manifest.webmanifest`, `/sw.js`, `/icons/*`
  (иначе браузер не установит приложение и не покажет его в «Поделиться»),
  `/u/<token>/tolmach.user.js`, `/api/import`, `/api/cron/*`.
- Кнопка на сайтах ходит по **отдельному ключу импорта**:
  `Authorization: Bearer <IMPORT_TOKEN>`. Ключ создаётся и отзывается на
  странице «Кнопка для сайтов», умеет только создавать главы и задачи.
  Cookie приложения из GM-контекста не используется (другой браузер,
  SameSite, Total Cookie Protection в Firefox).
- Защиту от запросов во внутреннюю сеть при скачивании по ссылке сохранить
  (exttran:web/lib/source.ts).

## Данные

Глоссарий — строки, а не один JSON-документ: в exttran маршрут читал документ
целиком и через 1–2 минуты записывал обратно, затирая ручные правки
(exttran:web/app/api/translate/route.ts:200, 387).

```
books(id, book_key, title, source_lang, site, style, narrator_person,
      narrator_gender, honorifics_policy, glossary_version, cover_url)
chapters(id, book_id, number, title_src, canonical_url NULL, next_url,
         content_sha256, created_at)
      unique(book_id, content_sha256)
chapter_paragraphs(chapter_id, idx, text)          -- idx 0 = название главы
translations(id, chapter_id, model, mode sync|batch, glossary_version,
             status, created_at)                   -- версии, не перезаписываются
translation_paragraphs(translation_id, idx, text)
chapters.current_translation_id                    -- указатель на текущую
paragraph_overrides(chapter_id, idx, text, source, created_at)  -- правки, откат
terms(id, book_id, en, ru, kind, gender NULL, aliases[], note,
      status proposed|checked, first_chapter)
addresses(id, book_id, from_term_id, to_term_id, form ty|vy, from_chapter,
          status proposed|checked)
summaries(chapter_id, source en|ru, text)
jobs(id, kind, chapter_id, state, next_chunk, lease_until, attempt, model,
     effort, mode, batch_id, glossary_version, reserved_usd, error)
     unique(chapter_id, kind) where state in ('queued','running','batched')
job_chunks(job_id, seq, text)                      -- поток, только вставки
batches(id, anthropic_id, collecting_until, state)
api_calls(id, job_id, purpose, model, batch, input, cache_write_5m,
          cache_write_1h, cache_read, output, thinking, usd, created_at)
          unique(job_id, chunk, attempt) / unique(batch_id, custom_id)
budget(month, limit_usd, spent_usd, reserved_usd)
reading_position(book_id, chapter_id, paragraph_idx, updated_at, device)
reports(id, kind, payload jsonb, created_at)       -- «Что-то не так»
settings(key, value)                               -- курс ₽/$, лимит, модели
```

- **Идентичность главы.** Адрес нормализуется: https, хост в нижнем регистре,
  без `#`, без `utm_*`, без `/` в конце, плюс правила по сайтам. Royal Road:
  канон `/fiction/{id}/chapter/{chapterId}`, ключ книги — fiction id; AO3 —
  work id (exttran:src/book.ts:35-45 сводил все книги сайта в один ключ).
  Вставленный текст и файл адреса не имеют: книга выбирается при импорте (по
  умолчанию последняя открытая), номер — из заголовка «Chapter N», правится.
  Повтор той же главы любым путём ловится по `content_sha256`.
- **Оригинал хранится** — только снятый текст, не страницы и не файлы.
- **Версия глоссария.** `books.glossary_version` растёт при каждой правке;
  перевод помнит, с какой версией сделан.

## Снятие текста

Один TS-модуль `lib/extract/` — и для сервера, и для кнопки на сайтах (её
собирает esbuild из того же кода, без `@require` с CDN).

- Результат — массив абзацев по блочным элементам `article.content`, а не
  `textContent`: тот склеивает `<p>` на минифицированном HTML
  (exttran:src/extract.ts:182-183, «really.Paragraph»).
- Выбор между Readability и запасным способом по плотности абзацев — одним
  правилом везде (exttran расходился: src/check.ts:98-101 против
  src/extract.ts:221-228).
- Скрытые строки Royal Road — обычные `<p>`, скрытые `display:none` во
  внутреннем `<style>`; Readability работает на клоне и их не видит.
  Текущая страница: пройти живой DOM, пометить невидимое (`getComputedStyle`,
  нулевой `offsetParent`), клонировать, удалить помеченное. Скачанные следующие
  главы: `DOMParser` → правила из `doc.querySelectorAll('style')` через
  `sheet.cssRules` с `display:none` → удалить `querySelectorAll(selectorText)`.
- Платность — по длине текста самой главы (меньше ~150 слов) плюс маркеры,
  только как подсказка. Не по маркерам на всей странице (exttran:
  route.ts:184 и src/ahead.ts:159 без условия на длину).
- Заглушка Cloudflare: заголовок `cf-mitigated: challenge`, или 403/503, или
  title «Just a moment» — сразу экран «сайт не пускает сервер, нажми кнопку
  на странице», без «всё равно перевести».
- Серверный `fetch`: `AbortSignal.timeout(10_000)`, предел 3 МБ, кодировка из
  `charset`, User-Agent только латиницей (exttran:src/config.ts:110-119).
- Подвалы переводчиков чистить только по краям (exttran:src/extract.ts:420-472,
  коммит 5954956). «Дальше»: rel=next → класс → текст ссылки → оглавление
  (exttran:src/extract.ts:294-392), якоря отрезать.
- **Файлы разбираются в браузере** (у функции Vercel тело до 4,5 МБ,
  EPUB и .mht больше): EPUB через JSZip (spine → xhtml глав), .mht — разрезать
  MIME-части, quoted-printable/base64 декодировать через
  `TextDecoder('utf-8')`. У файла Chrome в заголовке `type="text/html"`, а
  exttran брал пустую преамбулу (src/extract.ts:96-123). Картинки отбросить.
  На сервер — текст по главам, до ~100 КБ на запрос, с прогрессом.
- Вставка и «Поделиться» текстом: срезать по якорям (Previous/Next Chapter,
  Comments, название), показать предпросмотр с ценой до вызова модели.

## Кнопка на сайтах (юзерскрипт)

- Отдаётся с `/u/<token>/tolmach.user.js`, туда же `@updateURL` и
  `@downloadURL`; `@grant GM_xmlhttpRequest`, `@connect <host приложения>`.
  Страница «Кнопка для сайтов»: «Установить», запасной путь «скопировать →
  Violentmonkey → + → вставить», для Chrome — картинка с «Allow User Scripts»
  (Chrome 138+), самопроверка «кнопка работает». [проверить, этап 1]:
  открывается ли установка по ссылке `.user.js` в текущем Chrome на ПК.
- «Эта и следующие N»: состояние цикла в `GM_setValue`, продолжение при
  следующем открытии; пауза 3–5 с между главами, не больше 10–20 за раз;
  отправка с ключом идемпотентности по хешу текста. Фоновые вкладки на Android
  засыпают — цикл не должен зависеть от фоновой вкладки сайта.
- **Мост для «Дальше».** Скрипт работает и на домене приложения: из активной
  вкладки читалки берёт следующую главу через `GM_xmlhttpRequest` с куками
  пользователя. [проверить, этап 1, на телефоне, Royal Road]: пропускает ли
  Cloudflare такие запросы подряд.
- Браузер владельца на телефоне — **Kiwi** (Chromium, ставит дополнения из
  Chrome Web Store; архивирован, последняя сборка — апрель 2025). Выяснено в
  октябре 2026: в Chrome Web Store остались только MV3-версии менеджеров
  (Violentmonkey — с июля 2026, Tampermonkey — с 2024; MV2 убраны из магазина
  31.08.2026), а инъекция через `chrome.userScripts` в Kiwi сломана —
  разработчики обоих менеджеров это признают (Tampermonkey #2055, Violentmonkey
  #2598). Поэтому кнопку на телефоне ставим в **Firefox Android** +
  Violentmonkey с AMO (MV2, без переключателей); запасной — Edge Android +
  Tampermonkey/Violentmonkey с «Режимом разработчика». Страница «Кнопка для
  сайтов» говорит это прямо. Скрипт пишется без зависимостей от новых API
  Chromium. Chrome Android дополнений не поддерживает.
- Сайты-приложения (Next.js и т. п.) листают главы без перезагрузки, а
  менеджер запускает скрипт один раз на документ — скрипт сам следит за
  адресом и дорисовкой (docs/CONTRACTS.md, `tests/e2e/userscript-spa.mjs`).

## Задача перевода

- Создание: `insert … on conflict do nothing returning id`; если строка не
  вернулась — отдать id уже идущей задачи. Двойное нажатие, повтор отправки
  на плохой сети, два устройства и StrictMode не дают двойной оплаты.
- Захват: `update jobs set state='running', lease_until=now()+'90 s',
  attempt=attempt+1 where id=$1 and (state='queued' or (state='running' and
  lease_until<now())) returning *`. Каждая запись куска продлевает аренду.
- **Части.** Глава режется по границам абзацев на части ≤ ~1 500 слов,
  каждая — отдельный запрос со своим `max_tokens` (ожидаемый вывод × 1,5 +
  запас на обдумывание ~12–16K). Контекст части k: правила, стиль, термины
  части, сводка, 2–3 последних переведённых абзаца части k−1.
- **Эстафета.** Предел Hobby — 300 с на вызов, включая `after()`; при
  превышении 504 и ни `catch`, ни `finally` не выполняются. Внутри вызова
  обрабатывать части, пока прошло < ~200 с, затем передать эстафету: POST
  самому себе с внутренним секретом или отложенное сообщение очереди
  [проверить: Vercel Queues / Workflows на Hobby]. Опрос читалки или крон,
  увидевшие истёкшую аренду, перезапускают с первой незавершённой части;
  недописанная часть выбрасывается. Не больше 3 попыток на часть, затем
  «не вышло» с причиной. Prefill на моделях 5.x не поддерживается — дописать
  можно только переотправкой оставшихся абзацев.
- **Метки абзацев.** Перед каждым абзацем оригинала — `⟦idx⟧`, модель
  обязана повторить метку перед переводом; под одной меткой может быть
  несколько строк (реплики с новой строки — правило exttran:src/translate.ts:45-47).
  Метки вырезаются на лету при разборе потока. Пропущенная или повторная
  метка — провал проверки, заново переводится только этот idx.
  Цена: ~+250 токенов вывода на главу.
- **Поток в базу.** Только вставки в `job_chunks`, не чаще раза в секунду или
  по готовому абзацу; по завершении — перенос в `translation_paragraphs`.
  Поток показывается сырым, в конце подменяется правленым целиком (`polish`
  нельзя применять к кускам: exttran:route.ts:78-87).
- **Перед синхронным переводом** главы X сначала забрать пакеты, где есть X.
  Если X ещё считается — показать выбор «ждать / сейчас за полную цену».
  При «сейчас» пакетный результат сохраняется альтернативной версией, а не
  поверх (exttran переводил заново и перезаписывал: route.ts:161-166 против
  441-447, src/ahead.ts:303-318).

## Модели

| Модель | Цена $/1M вход/выход | Заметки |
| --- | --- | --- |
| `claude-haiku-5-5` | 0,10 / 0,50 (промпт ≤100K; выше ×5) | думает по умолчанию (effort medium); серверного fallback нет; prefill → 400 |
| `claude-sonnet-5-5` | 2 / 10, кэш-чтение 0,20 | effort по умолчанию high, уровни перекалиброваны; `thinking: disabled` → 400, минимальный режим `between_tools` |
| `claude-opus-5-5` | 4 / 20, кэш-чтение 0,20 | обдумывание не выключается ни на каком effort; effort по умолчанию medium |

- `output_config.effort` передавать **всегда явно**. Стартовые значения:
  перевод — Haiku low/medium, Sonnet low, Opus low; разбор терминов — low.
  Окончательно — по проверке на этапе 2. Токены обдумывания писать в
  `api_calls`.
- Запрос собирается отдельной функцией для каждой модели; поток и пакет —
  буквально одной функцией сборки (exttran, коммит d6e41cd).
- **Отказ** — HTTP 200 со `stop_reason: "refusal"`; начатое оплачивается,
  часть выбрасывается. Своя цепочка повтора на уровне части: Haiku → Sonnet →
  Opus → та же часть половинками. Серверный `fallbacks` не рассчитывать: у
  Haiku его нет, у Sonnet `"default"` не повторяет `general_harms`, в Batch не
  работает. `stop_details` читать с `?? null`.
- Ошибки: «Your credit balance is too low» → экран «на счёте Anthropic
  кончились деньги» (задачи остаются в очереди); «specified API usage limits» →
  «сработал лимит в Console»; 429 без `retry-after` не повторять.
- Не просить модель объяснять решения в тексте ответа — повод для отказа
  категории `reasoning_extraction`.
- Справка по API: навык `claude-api` (model-migration.md — разделы про
  Haiku 5.5, Sonnet 5.5, Opus 5.5; prompt-caching.md).

## Промпт

Порядок: правила → стиль книги → **метка кэша** → термины этой части,
персонажи с родом и «ты/вы» → сводка «что было» и конец прошлой части/главы →
текст с метками. Правила — из exttran:src/translate.ts:24-59, дополнить:
рассказчик и его род, перевод названия, метки абзацев.

Кэш (5 минут, запись 1,25×, минимальный префикс у моделей 5.5 — 512 токенов)
окупается только между частями одной главы. На экономию при чтении по главе
не рассчитывать; долю `cache_read_input_tokens` показывать на «Статусе».

Глоссарий в промпте — только термины, встречающиеся в части (по en и
aliases). Новые термины со статусом `proposed` идут с пометкой «предложено»,
а не как обязательные.

## Глоссарий и память

- Разбор главы до перевода: structured outputs, effort low. Модель видит
  существующие термины **с русскими написаниями** и существующие обращения
  (exttran давал только английские: src/glossary.ts:94-101, отсюда дубли).
  Возвращает: новые термины (с родом для персонажей), aliases, новые обращения
  со ссылкой на term id. Слияние — `insert … on conflict do nothing`;
  `checked` модель не меняет. Пополнение не останавливается после 15 глав.
- До проверки на этапе 2 разбор делает Sonnet (~0,8 ₽ за главу), потом —
  Haiku, если на этой задаче она не хуже.
- Сводка главы: 300–500 токенов, после главы; при подготовке пакета — по
  английскому тексту, последовательно, до отправки.
- **Подготовка пакета N глав** — цепочка задач с отметкой после каждой главы:
  для i по порядку — разбор терминов, слияние, сводка по EN; затем запросы,
  где у главы i — сводки 1…i−1, 2–3 последних EN-абзаца главы i−1, термины
  главы i. Опционально пауза «найдено 7 новых имён: проверить / так».
- **Переименование.** Режим «написание»: в абзацах, где в оригинале есть
  en-термин или alias, старая основа + окончание из закрытого списка
  (exttran:src/highlight.ts:20-25) → новая основа с тем же окончанием; каждая
  замена — строка в `paragraph_overrides`, предпросмотр списка, откат. Режим
  «переперевод»: затронутый абзац ± соседний, новый глоссарий, пакет,
  дешёвая модель, цена до нажатия. Переводы с `glossary_version` ниже текущей
  при сборе автоматически проходят режим «написание».
- Подсказки «проверь это» — из exttran:src/glossary-build.ts:146-170 (одно
  ru на разные en, ru===en, кириллица в en, нарицательное вместо имени).

## Готовый перевод

Читатель мог прочитать начало книги в чужом русском переводе. Переводить
эти главы заново — дорого; продолжать с чистого листа — имена разъедутся.
Поэтому главы готового перевода собираются в `ref_chapters` (кнопка «Т» на
русском сайте обходит главы сама — см. CONTRACTS «Кнопка на сайтах»), а
глоссарий по ним собирает фоновая задача `glossary_jobs` (`lib/server/glossary.ts`,
эстафета `/api/glossary/run`, аренда, резерв бюджета на каждый вызов — как
у перевода главы):

- **scan** — Haiku 5.5 читает главы пачками (до 4 глав и ~9 тыс. слов) и
  выписывает русские имена и термины в начальной форме с родом, заметкой
  «кто/что это» и номерами глав → `ref_terms` (счёт глав, первая/последняя).
  Пачка помечается прочитанной сразу (если текст главы с начала чтения не
  поменялся) — обрыв не заставит платить дважды. Ответ оборвался, не по
  схеме или запрос слишком длинный — пачка впредь читается по одной главе,
  одиночная глава пропускается; деньги, ключ и прочие ошибки останавливают
  задачу с причиной. Запись результата — одной транзакцией под блокировкой
  строки задачи: «Остановить» и «Убрать» ждут её, а после них не пишется
  ничего.
- Номер главы при приёме (`lib/server/refimport.ts`, `lib/core/refnumber.ts`):
  части («5.1», «5.2») складываются в одну главу; том с нумерацией заново —
  по ожидаемому номеру обхода, а в новом обходе — по ссылке «назад» на уже
  взятую главу; глава под тем же номером с другого адреса и с другим
  текстом не затирается (409). Адреса сравниваются без #, меток (utm_*,
  ysclid), «/» в конце, www и схемы. Первая часть, пришедшая после второй,
  встаёт в начало главы; часть без связи с прошлой главой (нет ни ожидаемого
  номера, ни знакомой ссылки «назад») к чужой главе не дописывается.
- **align** — до 12 последних глав, что есть и по-английски, и в готовом
  переводе: пары «английское → русское» → `terms` с `source = reference`.
  Готовый перевод главнее разбора: русское написание у предложенного
  моделью (`auto`) термина меняется; проверенное человеком — никогда.
- В конце `ref_terms` связываются с терминами по русскому написанию.
  Несвязанные — подсказки: до 150 свежих и частых уходят в разбор новой
  главы («ИМЕНА ИЗ ГОТОВОГО ПЕРЕВОДА»), и модель берёт их написание; после
  разбора связывание повторяется.
- Своего перевода прошлой главы нет — «конец предыдущего текста» берётся из
  главы готового перевода с номером N−1: первая своя глава продолжает тон.
- Цена — до запуска на странице книги (`estimateGlossaryUsd`): ~0,1 ₽ за
  главу на Haiku. Расход пишется в `api_calls` с `purpose = glossary`.
- Главы готового перевода читаются в Толмаче (`/book/:id/ready/:number`,
  бесплатно): в оглавлении на номер одна строка (свой перевод → готовый →
  своя глава без перевода, `lib/client/toc.ts`), «Назад»/«Дальше» ходят и
  между своими, и между готовыми главами (`lib/core/ready.ts`). Своя глава
  без перевода, у которой есть готовый перевод, предлагает «Читать готовый
  перевод · бесплатно» до платного «Перевести самому». Место чтения в
  готовых главах не запоминается (таблица места ссылается на свои главы).

## Проверки

- Бесплатные, в приложении: совпадение меток абзацев; латиница в русском
  тексте (белый список из глоссария: HP, LV…); отношение длин абзацев
  0,6–2; неверное написание термина — кириллическое слово, чья основа по
  Snowball-стеммеру отстоит от основы термина на 1–2 правки и не совпадает
  (каждое слово составного термина отдельно, без учёта регистра). Отсутствие
  термина нарушением не считается («он», «старик» — законно).
- «Несуществующие слова» нужны полным словарём русского; на Vercel это дорого
  по CPU. Для проверки на этапе 2 — считать в сессии Claude Code через
  pymorphy3 по выгрузке. В приложение — только если основой станет Haiku, и
  после замера размера и времени загрузки (вариант — фильтр Блума словоформ).
- Автопочинка выключена по умолчанию; кнопка «Починить N мест ≈ X ₽»;
  в настройках — автопочинка с потолком (например, 5 абзацев и 1 ₽ на главу).
- `polish` из exttran:src/polish.ts переносится как есть, вместе с тестами.

## Пакеты (наперёд за полцены)

- `custom_id = job_<id>`; результаты приходят в любом порядке — ключ по
  custom_id. Хранятся 29 дней.
- Сбор: при открытии приложения и читалки, перед синхронным переводом главы
  из пакета, ежедневный крон (Hobby: раз в сутки ±59 мин) как подстраховка,
  и отложенная проверка через 10–15 минут после отправки с повтором
  [проверить механизм, этап 4]. Захват сбора:
  `update batches set collecting_until=now()+'2 min' where id=$1 and
  (collecting_until is null or collecting_until<now()) returning`.
- `errored`/`expired` — переотправить один раз; отказ внутри `succeeded` —
  синхронный повтор другой моделью после подтверждения.
- Расход пакета ×0,5 (exttran не учитывал: src/ahead.ts:293 → src/cost.ts:29-34).

## Бюджет и учёт

- Цена считается по `message.model` из ответа и таблице цен по моделям
  (вход, выход, запись кэша 5 мин/1 ч, чтение кэша), пакет ×0,5. Курс ₽/$ —
  в настройках.
- **Резерв** перед каждым вызовом и отправкой пакета:
  `update budget set reserved_usd=reserved_usd+$worst where month=$m and
  spent_usd+reserved_usd+$worst<=limit_usd returning`, где
  `$worst = вход × цена входа + max_tokens × цена выхода`; после вызова резерв
  закрывается фактом. Иначе два устройства и пакет проходят проверку лимита
  одновременно.
- На 80% — предупреждение; на 100% — выбор: стоп / дешёвая модель до конца
  месяца / поднять лимит.

## Читалка и офлайн

- Читалка — **клиентский компонент**, рисует главу из JSON
  (`/api/chapters/:id`) или из IndexedDB одним кодом. Иначе офлайн на этапе 4
  потребует переписать её (у App Router нет своего service worker; RSC-переходы
  без сети не грузятся).
- Service worker руками (`public/sw.js`), без плагинов: оболочка и шрифты в
  precache; API — сначала сеть, без сети — IndexedDB; ответы с редиректом и
  401 не кэшировать. «Скачать N глав» — `idb-keyval`: абзацы оригинала и
  перевода, термины. `navigator.storage.persist()`, показ занятого места.
- Место чтения без сети копится и синхронизируется, побеждает последняя
  запись по времени.
- Плашка «Есть новая версия — обновить» при смене версии сборки; номер версии
  и SHA на «Статусе» (exttran, коммит 0488b69: полдня ушло на «это свежая
  страница или кэш?»).
- Share Target: `method POST`, `enctype multipart/form-data`, файлы
  `text/html`, `multipart/related`, `message/rfc822`, `.mht`, `.mhtml`.
  Service worker разбирает formData, кладёт в IndexedDB, 303 на `/share`.
  Работает только для приложения, установленного из Chrome; Firefox Android
  `share_target` не поддерживает.
- Wake Lock (Chrome Android 84+, Firefox Android 126+), зоны касания и свайп,
  тема из localStorage в try/catch после первой отрисовки
  (exttran:web/app/read/reader.tsx:96-139).
- Защита от двойного эффекта в StrictMode — по всему запросу целиком
  (exttran:web/app/read/reader.tsx:141-168).

## Нагрузка на бесплатные лимиты

- Neon Free: база засыпает через 5 минут простоя; время работы в месяц
  ограничено (~100 CU-часов, при 0,25 CU ≈ 400 ч ≈ 17 суток бодрствования)
  [проверить по текущей странице цен]. Значит: опрашивать базу **только** пока
  идёт задача и страница видима (`document.visibilityState`), раз в 1–2 с, с
  курсором `since=seq`; в остальное время не опрашивать; готовность пакетов
  проверять на сервере.
- Vercel Hobby: ограничены Active CPU и время функций; снятие текста делать в
  браузере, jsdom на сервере — только запасной путь для «по ссылке».
- Еженедельная выгрузка библиотеки (JSON + EPUB) — страховка от потери
  бесплатной базы.

## «Что-то не так»

Отчёт в `reports`: снимок того, что прислала кнопка или вставка, результат
снятия текста, запрос и ответ модели, цена, версия сборки. Читается через
защищённый эндпоинт по номеру — сессия Claude Code разбирает его сама, не
открывая сайт (облачный IP получает 403 от Royal Road и др.; так в exttran не
воспроизвелись две поломки, коммит 02c3fb8).

## Защиты, добавленные по итогам проверки кода этапа 1

- **Вход:** неудачи считаются по адресу клиента (`x-real-ip` на Vercel);
  попытка сначала записывается неудачной, потом считается — одновременные
  запросы не проходят мимо лимита. Удачный вход очищает неудачи адреса.
  Адрес возврата после входа проверяется разбором URL (табуляции и переводы
  строк браузер выбрасывает).
- **Кнопка:** `@inject-into content` — скрипты сайта не дотянутся до ключа.
  Перед выпуском нового ключа — предупреждение, если ключ уже есть
  (`GET /api/button-token` → `{exists}`).
- **Задача перевода:**
  - вызов модели идёт «под присмотром»: аренда продлевается таймером, пока
    вызов идёт; к 270 с от начала захода вызов обрывается сигналом, чтобы
    успеть учесть расход;
  - расход учитывается и у оборванных вызовов (по событиям потока), и у
    разбора терминов, который не разобрался по схеме (`messages.create` +
    свой разбор вместо `parse`);
  - ответ запасной модели серверного повтора оценивается по её цене
    (`priceSpec` в `lib/core/cost.ts`); резерв для моделей с серверным
    повтором — вдвое: оплачиваются и отказ, и ответ;
  - резерв бюджета записан и на задаче (`jobs.reserved_usd`): следующий
    заход возвращает резерв, оставшийся от убитого;
  - при продолжении части переводятся только недостающие абзацы; на часть —
    не больше трёх заходов (`chunk_tries`), потом заменитель;
  - повторы после временных ошибок считаются отдельно (`retries`, до 5 на
    часть), а не по числу эстафет;
  - состояние задачи пишет только её текущая попытка (`setJobStateIf`);
  - «Повторить» после сбоя продолжает ту же версию перевода той же моделью
    (оплаченные части и разбор терминов не повторяются); читалка показывает
    уже переведённое и потраченное у остановленной задачи;
  - «Продолжить» после лимита запускает каждую задачу отдельным вызовом.
- **Цена на экранах** включает поиск имён (`estimateTranslationUsd` с
  `extractModel`).
